# 阅读与知识内化闭环

本轮将采集后的摘抄组织为可复看、可关联的本地知识库。代码及模拟测试不代表真实模型效果或真机验收，所有真实远端调用和上线操作须单独授权。

## 功能入口与契约

| 需求 | 当前实现与入口 |
|---|---|
| 两级标签 | 一级固定为人文、商业、技术、认知、职场、社会、随笔，当前单选；二级优先提示复用已确认历史池，标准化精确复用，否则待确认。知识页支持确认、合并、删除、重命名；固定一级不可改。没有独立后台 Web 管理站。 |
| AI 解读 | 详情页完整分析生成核心释义、场景应用、认知启发。Prompt 分隔指令与数据，要求忠于原文、信息不足明确说明；结构校验不能保证语义绝对正确，仍需核对。 |
| 核心关联 | 详情页先补全远端向量，从本地正余弦 Top-20 中保留最近两张，再以 0.7 相关性 / 0.3 去冗余的 MMR 重排选出最多5张，逐对 LLM 判断；有 ID、摘要、比较焦点、双方主张、适用边界和连续原文证据。候选可确认/拒绝，确认关系形成内部网络。 |
| 书籍 | LLM 候选须经 OpenLibrary 标题和可用作者匹配、合法 works key 校验；验证失败不展示。分语义匹配、仅推测；高确定只能通过用户核对页码/章节及原文保存出处证据，不把“书存在”冒充“摘抄出自该书”。 |
| 文章 | 三个互补检索关键词 → Brave 搜索 → 白名单网站实际抓取 → 结合当前摘抄判断具体阅读增量并摘要。过滤无关内容、仅关键词重合、不可访问、登录、验证码、目录页和不支持摘要的引用；最多校验8篇、返回3篇。同 URL 的 fragment 去重，保留查询参数，已选标题去重。返回关联类型、为什么读、摘抄引文及正文引文，详情及导出均可见。URL 带检查时间，不承诺未来永久可访问。 |
| 个性化 | 基于全部当前卡片的一级主题计数选两个低覆盖方向，过滤已读及既往推荐，主题/作者/书名去重。低覆盖不等于读者能力不足；暂非深层用户能力画像。 |
| 存储导出 | 原始 JSON 备份独立于 AI 结果；本地完整 Markdown 含原文、解读、标签状态、已确认关系、书籍、文章。默认 ZIP 包含 raw/ 与 reflections/，可导入 Obsidian。 |
| 复习 | SM-2 风格间隔重复（不是唯一的“艾宾浩斯算法”），再次/困难/记住/轻松四档反馈，按日预算 3–5 张；不足时不凑数，同日已完成计入预算。编辑正文后旧复习计划失效。 |
| 周报与提问 | 高价值摘抄生成 2–3 题，批注独立加密保存。复习页手动生成本周报告；授权后后台生成上一自然周报告，包含统计、高频已确认标签和有原文引用的观点/思考主线。 |
| 入口 | 采集、卡片、知识、复习、设置五个 Tab；桌面小组件显示待复习数量并打开复习页。复习队列与周报可经预览手动创建 Notion 子页面。 |

关键词检索仅为已有的轻量辅助，不替代向量语义检索。相似分数并不代表观点一致，负余弦也不是对立观点，不参与候选。多样性重排是启发式去冗余，不保证召回所有对立观点。同主题、支持、反驳、延伸、例证由 LLM 判断；反驳必须针对可比条件下的同一命题，不同条件只能说明边界或提出问题。knowledge-v2 要求每个无序卡片对最多一条关系，非同主题双方引文至少12字（不足时全文），拒绝过短片段和矛盾分类；语义正确性仍需人工核对。无充分证据允许零关系。导出仅包含已确认关系，拒绝或已确认的卡片对不再重复召回。证据、分析、向量都与原文 revision 绑定；编辑后旧结果不可冒用。

## 外部数据流与配置

- 完整分析：Android → 已配置 backend → backend LLM/OpenLibrary，可选 Brave；发送当前原文、已确认二级池、已读标题。即使单卡配置 BYOK，本轮增强分析/周报/画像仍走 backend，确认框明确说明，不宣称完整 BYOK 对等。
- 语义索引：Android → backend `/v1/reading:embed` → 固定 `https://api.openai.com/v1/embeddings`。同时配置 `CLIPMIND_EMBEDDING_MODEL` 和 Secret `OPENAI_API_KEY`；必须使用与响应一致的精确模型身份。向量按模型/修订缓存并加密落本地，检索不上传向量库；这不是离线端侧 embedding 推理。
- 关系判断：本地多样性重排后的最多5张 → 每次仅源卡与一个候选 → 配置的 backend 或 BYOK 归纳路线。已有鉴权、来源范围及证据校验继续生效。用户撤销、来源或配置变化会阻止后续发送/写回；已接受请求的费用不一定能取消。
- 文章：Secret `BRAVE_SEARCH_API_KEY` 启用。只抓取 `mp.weixin.qq.com`、`zhuanlan.zhihu.com`、`sspai.com`、`infoq.cn`、`www.infoq.cn` 的 HTTPS 页面；禁代理/重定向，连接时检查 DNS 的私网及保留地址。正文清洗后前 8000 字与当前摘抄交同一后端模型判断阅读价值；Brave 仍只接收3个关键词，不发送摘抄。每篇增加最多6000字摘抄上下文，费用可能增加，不新增服务商或自动重试。无搜索配置时明确告知，无合格文章返回 `NO_RELEVANT_VERIFIED_ARTICLES`，不生成假文章。
- Notion：独立 Keystore 加密 Token 与父页 UUID，仅调用固定 `https://api.notion.com/v1/pages`（版本 `2022-06-28`）。集成权限需由用户授予指定父页。用户预览后逐次确认，不后台自动发布，不自动重试；先落去重凭据再发请求，失败或结果未知请先人工核对远端。普通文档删除不能删除去重凭据。

所有 `/v1/reading*` 沿用服务端 Bearer 鉴权；仅本地开发可关闭鉴权，不引入匿名特权接口。当前后端是单用户 Token 模式，不提供多用户隔离。密钥必须通过环境 Secret 或客户端密钥存储注入，不放到源码、日志或请求内容中。capabilities 只说明已配置，不代表服务商连通或效果验收。

## 预算、调度与持久化

索引最多 2000 张当前卡片，每张最多 6000 个 Unicode 字符，向量请求每批最多 16 张且总计 16000 字；首次建库可能产生多批费用。语义判断最多 5 次，不用关键词伪装降级成功。超限/敏感内容阻断，不静默截断。周报每次原文总计最多 16000 字，超限需减少当周内容后再生成，尚不支持无限历史分层归纳。

阅读 POST 请求最大 128 KiB、25 秒超时，与知识归纳共享两个并发槽。索引模型变化后需重建，维度或响应顺序错误不会入库。端侧 UI 和后台付费操作共享互斥门，避免同进程并行重复请求；不承诺跨设备的计费幂等。

提醒、自动分析、自动关联、自动周报默认关闭，设置页逐项告知持续授权范围。WorkManager 每 12 小时尽力调度，并在安排时触发一次刷新，不保证精确时刻。每轮最多分析 3 张、关联 1 张源卡；上一周报告生成一次。尝试标记先于远端请求，失败显示任务记录、不隐式重试；需要用户手动重试。Android 13+ 需通知授权，小组件不显示摘抄原文。

Room v7 显式迁移保留既有密文，并增加阅读结果、向量、复习计划、独立文档。正文/AI 结果/向量/原始 JSON/批注/周报使用应用 Keystore 加密；分类名称、关联 ID、时间等索引元数据不属于全库加密。服务端原始备份是 AES-GCM JSON，结构化 store.json 和 Markdown 仍需操作系统目录保护，不宣称后端全量加密。

批注草稿只在 ViewModel 内存跨 Tab 保留，最多 20 份、每份 10000 字符，进程死亡会丢失，保存后才持久化。删除卡片是软删除，原始备份、独立批注/周报、Notion/Obsidian 副本有各自保留生命周期，不等于安全擦除。明文 ZIP 可能包含独立历史笔记；分享前需复核。原始 JSON 备份不依赖 AI 成功，但本轮不新增一键 ZIP 恢复/导入界面。

本地标准导出是增强知识库的完整输出路径；原来的服务端 Obsidian 自动同步不自动携带本地文章、确认关系和批注，不是双向同步。服务端和本地都保留原始复制段落，去重可以规范化但传输 SHA-256 按真实原文字节计算。

## 验证与人工门槛

1. 本地：运行 Go 单测/竞态检测/vet，Android JVM 单测/lint/Debug 构建，SQLite 迁移检查；测试只使用 mock HTTP 和内存/临时数据库，构建指向 `https://example.invalid/`。
2. 人工授权的 BOE：使用脱敏摘抄和专用测试密钥，核对向量召回质量、两类关系及引文、中文书籍匹配、实际文章抓取、失败提示和费用；测试不足五条候选及无相关关系，不要求模型强造结果。
3. 真机：备份后验证 v6→v7 升级、编辑/删除/撤销并发、后台休眠与时区切换、通知授权和小组件；确认五个 Tab、草稿保留、复习预算、周报引用和实际 Notion 子页。
4. 渐进上线：单独提交变更审批，本次先小范围更新兼容 knowledge-v1/v2 的客户端，再经人工确认更新输出 v2 的后端；旧客户端只接受 v1，未完成兼容更新前不得切换后端。新客户端按原 v1 规则读取历史归纳，新增文章字段可缺省，不迁移或重写历史缓存。所有新增后台开关保持关闭，关键节点人工确认。使用脱敏 BOE 样本比较无关推荐率、支持/反驳误判、候选覆盖与费用，观察错误/超时后再人工决定扩量；禁止由本轮脚本自动部署或切流。
5. 异常退出：人工关闭新增任务并停止扩量，保留数据库和原始备份，禁止清库或安装不兼容旧 Room 版本；恢复方案须另行审批并先在 BOE 验证。

本轮允许的 Git 提交/推送仅同步源码，不启动服务、不安装到设备、不执行生产变更。真实服务商、Notion、Shizuku/OEM 兼容及数据恢复演练尚需上述人工验收。
