# ClipMind Phase 1 安全基线

## 不变式

1. 原始剪贴文本不得进入 Logcat、服务日志、Metrics 标签、异常堆栈或通知正文。
2. Shizuku 仅用于最小剪贴板能力，不提供任意 Shell 命令入口，也不导出可被第三方调用的 Binder。
3. 文本必须先经过端侧安全过滤并加密落盘，再进入可重试 Outbox。
4. 服务端必须重复执行安全过滤；只有通过后才允许调用外部模型。
5. Raw backup 使用每环境独立的 AES-256-GCM 密钥，生产环境缺少密钥时拒绝启动。
6. LLM 输出必须通过结构化校验和二次敏感信息检查，不接受模型自行生成的外部 URL。
7. 所有写接口都必须有幂等键；重试不能生成重复卡片。

## Phase 1 威胁边界

- **Shizuku 服务不可用**：暂停自动采集，保留分享面板和手动粘贴入口；已落盘数据继续保留。
- **权限被撤销或 Binder 死亡**：立即进入可见降级，禁止绕过授权切换到无障碍服务。
- **第三方模型超时或限流**：Pipeline 保留 checkpoint 并重试；原文备份不受影响。
- **Obsidian 路径不可写**：卡片保持待同步状态，允许重试，不删除已生成版本。
- **删除权与长期备份冲突**：Phase 1 仅提供可执行的删除策略接口；最终保留期限需产品与法务确认。

## 上线前检查

- Android 11–16 及目标厂商 ROM 真机权限矩阵通过。
- Shizuku 首次激活、重启恢复、权限撤销和服务死亡均有清晰提示。
- 敏感测试集没有原文日志泄漏。
- 生产密钥、模型令牌和知识库路径均从安全配置注入。
