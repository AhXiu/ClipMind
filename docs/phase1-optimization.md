# 第一阶段优化与验证

## 范围

- Android 展示服务端或 BYOK 的总结、解读、行动建议与模型来源。服务端结果只以加密形式落盘，获取后可离线阅读。
- 分离分析与上传/Obsidian 状态，服务端分析完成不再依赖客户端缓存字段。
- 详情订阅当前卡片数据；支持 AI 标签采纳、原文/摘要复制、关联卡片跳转。
- 待确认上传入口、删除确认、系统返回时的编辑草稿保护。手动记录失败保留输入，语音/分享先进入草稿。
- 草稿仅保留在 ViewModel 内存中，支持页面切换和配置变更，不写入明文 Bundle；进程终止后不保证恢复。

## 任务与版本

本地卡片 ID 不变。`contentRevision` 在正文实际修改时增加；修改同时清空 AI 缓存，关系标记为 STALE，正文转为 LOCAL_ONLY，等待用户重新提交。人工标签保留。

`clientCaptureId` 作为当前上传/分析任务 ID。重试原任务不更换 ID，不清空 BYOK 缓存；显式重新生成分配新任务 ID。READY、UPLOADING、RETRYABLE_ERROR 状态禁止编辑/新建生成任务，防止已发出的请求与新正文混淆。

服务端新接口 `POST /v1/cards/{cardId}/analyses` 复用采集验证与加密备份，创建新 Capture 并原子替换原 Card 的 CaptureID。Card ID、历史版本和旧原文备份保留；旧任务不再参与调度，旧 Capture/Card 回写被拒绝。新任务强制 confirm，用户确认前不覆盖已有 Obsidian 文件。

重新生成要求原卡片处于 awaiting_confirm、synced 或 ai_failed；处理/同步中的卡片返回 409，客户端保留同一任务退避重试。此实现沿用现有单体单写者存储模型，不扩展为多实例服务。

Android Room 4 -> 5 只增加 `contentRevision` 和 `encryptedServerAnalysis`，不清表或使用破坏性迁移。删除仅软删除本机卡片，不撤销已发出的请求、不删除云端/导出副本，确认框明确提示这一边界。

## 本地验收

1. 后端运行 `go test -race ./...` 和 `go vet ./...`，使用模拟模型/临时目录，不访问真实模型。
2. Android 使用 JDK 17+、SDK 35，运行 `./gradlew testDebugUnitTest assembleDebug -Pclipmind.baseUrl=https://example.invalid/`。构建成功后仍需真机 UI 和 Keystore 验证。
   在仓库根目录运行 `python3 android/scripts/check_migration.py`，可独立验证实际迁移 SQL 和旧任务/响应隔离条件。
3. 在 BOE 人工确认配置后，验证服务端/BYOK 两条链路、断网重试、401、后台中断、编辑敏感信息、同任务重复请求、旧响应晚到、删除时在途任务和 AI 中途关闭。
4. 用脱敏 v4 数据库验证升级后密文、标签、关联和历史同步元数据保留；Room schema 校验和真实迁移测试为上线前必过项。
5. 确认重复生成仍对应同一 Obsidian 文件；生成失败时旧文件保留，新版本未经用户确认不会写入。

## 渐进上线与人工卡点

此文档仅描述流程，不执行任何部署、线上请求或配置修改。

1. 先完成本地测试和 BOE 联调，由负责人审核接口、数据迁移和隐私边界。
2. 后端先升级，保留旧批量采集接口兼容；Android 新版本通过内部测试渠道小范围分发，旧后端没有新接口时应可见失败，禁止降级成新建重复卡片。
3. 人工检查分析成功率、重复任务数、内容版本错配、迁移失败率、模型调用量及同步失败率；任何越权、敏感外发、错版本覆盖均停止扩大范围。
4. 扩大范围必须再次人工授权，遵守审批和封禁窗口，不由 Agent 执行发布。
5. 出现问题时由人工暂停 AI 提交、保留本地采集。不得直接将 Room v5 降级到 v4，不得清空数据库；优先前向修复。后端恢复旧程序前须评估旧调度器对历史 Capture 的处理，不能直接回退旧二进制。

## 后续范围

语义召回、关联候选生成、多卡主题归纳、分页搜索和完整视觉重构不在本阶段。后续已在[第二阶段](phase2-knowledge.md)加入本地词语关联候选和选定卡片的 LLM 归纳；向量语义检索仍未引入。
